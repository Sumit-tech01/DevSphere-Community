# Support

DevSphere is a volunteer-run, free community. This page explains where to ask for help so your question reaches the right people and stays useful for everyone who comes later.

## Where to get help

| I need help with... | Best place |
| --- | --- |
| A programming or technical question | **Questions & Help** in [GitHub Discussions](https://github.com/Sumit-tech01/DevSphere-Community/discussions) |
| Feedback on a project | **Project Showcase** discussion |
| Finding collaborators or teammates | **Collaboration** discussion |
| Internships, jobs, or career advice | **Career & Opportunities** discussion |
| A bug in this repository | [Open a bug report](https://github.com/Sumit-tech01/DevSphere-Community/issues/new?template=bug_report.md) |

| A security vulnerability | Follow [SECURITY.md](SECURITY.md) — never post it publicly |
| A conduct or safety concern | Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |
| A contribution workflow question | Read [CONTRIBUTING.md](CONTRIBUTING.md), then ask in Discussions |
| GitHub account or platform support | [GitHub Support](https://help.github.com/) |

## Before you ask

A little preparation gets better answers:

1. **Search first.** Check the documentation, existing discussions, and issues. Your question may already be answered.
2. **Read the error message.** Include the exact message, not a paraphrase.
3. **Reduce the problem.** Share the smallest example that reproduces the issue.
4. **Explain what you tried.** Mention the approaches that did not work and why.
5. **Describe the expected result.** Tell us what you expected and what happened instead.
6. **Include your environment.** Operating system, language version, framework version, and relevant tooling.
7. **Remove secrets.** Never include passwords, tokens, private keys, or personal data.

## How to ask a good technical question

A useful question usually contains:

- **A specific title** that summarizes the problem.
- **Context:** what you are building and the relevant constraints.
- **A minimal reproduction:** code, commands, or a link to a small repository.
- **The actual output:** full error messages and logs, with sensitive values removed.
- **The expected output:** what success looks like.
- **What you have tried:** documentation, searches, and experiments.
- **Your environment:** versions and platform details.

Avoid:

- "It doesn't work" without details.
- Posting the same question in multiple categories.
- Asking people to debug a large private codebase with no reproduction.
- Sharing credentials or asking others to log in to your account.
- Pressuring volunteers for an immediate response.

## How to help others

- Read the whole question before answering.
- Ask clarifying questions when the problem is ambiguous.
- Explain the reasoning, not only the fix.
- Link to official documentation when possible.
- Be kind when correcting a misconception.
- Mark a reply as the answer in **Q&A** discussions when it resolves the question.

## Response expectations

DevSphere is maintained by volunteers across different time zones. We aim to respond when we can, but we cannot guarantee a response time or a solution.

- Community questions are usually answered by other members as well as maintainers.
- Repository issues are triaged on a best-effort basis.
- Security reports follow the targets in [SECURITY.md](SECURITY.md).
- Repeated pings or private messages do not speed up a volunteer response.

If a discussion has received no reply after a reasonable period, you may add a polite follow-up with new information. Please do not bump the same question repeatedly.

## Free support only

DevSphere does not offer paid support, consulting, or guaranteed response times. Recommendations made by community members are provided in good faith; verify important decisions independently.

## Private matters

For sensitive conduct or security concerns, use the private reporting routes in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) and [SECURITY.md](SECURITY.md). Do not use public discussions for private or sensitive information.

For other private matters, use the contact method listed on [@Sumit-tech01's GitHub profile](https://github.com/Sumit-tech01). Please keep community support in public discussions so that everyone can learn from the answers.

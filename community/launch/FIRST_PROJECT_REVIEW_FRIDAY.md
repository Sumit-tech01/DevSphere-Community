# 🔍 First Project Review Friday — Bring One Project, One Question

> **Draft discussion post.** Intended for **Project Showcase**. Publish manually only. Do not publish automatically. No submissions are invented to fill the thread.

The first **Project Review Friday** session opens on the first Friday after this announcement at **09:00 UTC**.

Project Review Friday is a weekly thread for specific, constructive feedback. It is not a roast, a score, or a popularity contest. The goal is one or two changes the builder can actually make.

## How to submit

1. Choose **one** project and **one** specific question.
2. Open a new Project Showcase discussion titled `Project Review Friday — <project name>`.
3. Use the [Project Review template](https://github.com/Sumit-tech01/DevSphere-Community/blob/main/community/templates/PROJECT_REVIEW_TEMPLATE.md).
4. Include a working repository or demo link, the current stage, and the part you want reviewed.
5. Do not post only a link. A link drop is not a review request.

## What to include

- What the project does and who it helps.
- A working demo or repository link.
- The current stage: idea, prototype, MVP, live, or maintained.
- The technology stack and any constraints.
- Known limitations.
- The specific feedback you want: usability, accessibility, performance, code structure, documentation, naming, or positioning.
- Whether you want collaborators or only feedback.

## How to review

Use four short sections:

| Section | What to write |
| --- | --- |
| **What works** | Name one or two specific things that are effective. |
| **Questions** | Ask about assumptions, constraints, or decisions you do not understand. |
| **Suggestions** | Offer one or two concrete changes, with a reason and a trade-off. |
| **Suggested next step** | Name the smallest useful thing the builder could do next. |

A short review is welcome. "The README explains the problem clearly. I would add a screenshot of the empty state because that is where I got stuck" is more useful than generic praise.

## Host note

The host opens the thread when at least one reviewer is available. Submissions stay open through the following week. A Friday with no submissions or no reviewers is skipped, not filled with invented content. If you want to review a project, reply in the submission thread and say which part you can review.

## Review etiquette

- Critique the work, not the person.
- Ask before rewriting someone's project.
- Do not demand unpaid labor or a merge.
- Do not use the thread to recruit, sell, or promote an unrelated product.
- Do not share private code, credentials, or customer data.
- Do not dogpile. If several reviewers agree, consolidate instead of repeating.
- Respect the builder's stated scope and constraints.

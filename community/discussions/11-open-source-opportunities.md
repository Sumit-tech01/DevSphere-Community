# Open-Source Contribution Opportunities — Find Your First Issue

Open source is one of the best ways to learn in public: you read real code, receive real review, and work with people who care about the same problem.

It can also be intimidating. Where do you start? How do you know whether an issue is still open? What if your pull request is rejected?

This thread is for sharing beginner-friendly opportunities, asking for help, and telling the story of your first contribution.

## For maintainers: share an opportunity

Use this format:

```markdown
## Project

Name and one-sentence description.

## Repository

Link to the project.

## License

## Issue or task

Direct link to the issue or a short description.

## Skill level

Beginner / Intermediate / Advanced

## Skills needed

Languages, frameworks, or documentation skills.

## Estimated effort

Hours or a rough range.

## Mentorship

Will someone review questions and the first pull request? What is the expected response time?

## How to start

Setup instructions or a link to CONTRIBUTING.md.

## Good first issue?

Yes or no. If yes, explain why.
```

## For contributors: find a good first issue

Look for:

- A clear issue description with expected behavior.
- A maintainer who has confirmed the task is open.
- Setup instructions that work.
- A project with recent activity and respectful review.
- A task scoped to a few files, not an architectural rewrite.
- A `good first issue` or `help wanted` label.

Before you comment:

1. Read the contribution guide.
2. Search for existing pull requests and discussions.
3. Reproduce the issue locally.
4. Ask whether the task is still available and whether your approach is welcome.
5. Start small and communicate early.

## Share your first-contribution story

Tell us:

- What project did you contribute to?
- What did you change?
- What was harder than expected?
- What did the review teach you?
- What advice would you give to someone making their first contribution?

Stories help demystify the process. They also show that rejection and revision are normal parts of open source.

## For maintainers: make contribution easier

- Label beginner-friendly issues.
- Write a `CONTRIBUTING.md` with setup and test commands.
- Keep a `good first issue` list current.
- Respond to first-time contributors with patience.
- Explain the reasoning behind requested changes.
- Credit contributions accurately.
- Close stale issues with a clear explanation.

## Safety and integrity

- Do not post issues that require contributors to pay, join a private group, or share sensitive data.
- Do not submit mass, low-quality pull requests to many projects.
- Do not remove license notices or attribution.
- Do not pressure maintainers for free labor or immediate review.
- If you find a security issue, follow the project's security policy; never disclose it publicly.

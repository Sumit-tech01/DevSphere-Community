# Web Development — Build, Debug, and Discuss the Modern Web

The web is one of the most accessible places to build — and one of the easiest places to accumulate unnecessary complexity.

This category is for thoughtful conversation about frontend, backend, accessibility, performance, and the craft of shipping for the browser.

## What belongs here

- HTML, CSS, and JavaScript questions.
- React, Next.js, Vue, Svelte, and other frontend frameworks.
- Node.js, APIs, databases, and server-side rendering.
- Accessibility, responsive design, and design systems.
- Performance, Core Web Vitals, and debugging.
- Testing, deployment, and developer experience.
- Career questions specific to web development.

## Share your work

When sharing a project or a bug, include:

- **The goal:** what should happen?
- **The actual behavior:** what happens instead?
- **A minimal reproduction:** a small repository, CodePen, or code snippet.
- **The environment:** browser, framework version, operating system, and relevant tooling.
- **What you tried:** documentation, experiments, and errors.
- **What you need:** a diagnosis, a review, or a design opinion.

## Discussion starters

- What is your favorite way to structure a React component tree?
- How do you decide between server rendering, static generation, and client rendering?
- What is a CSS layout problem that took you longer than expected?
- Which accessibility issue do you see most often in real projects?
- How do you measure whether a performance optimization actually helped?
- What is one web platform feature more developers should learn?
- What is a framework trade-off you changed your mind about?

## Accessibility is not optional

Accessible design is part of quality. When asking for feedback, consider:

- Keyboard navigation and visible focus.
- Semantic headings and landmarks.
- Color contrast and text size.
- Form labels and error messages.
- Alt text for meaningful images.
- Reduced motion.
- Zoom and small-screen behavior.

A beautiful interface that excludes people is not finished.

## Debugging together

A useful bug report is a gift. Please avoid:

- "It doesn't work" with no context.
- A screenshot of code instead of a code block.
- A link to a huge private repository and no reproduction.
- Posting the same question in several categories.
- Asking someone to log in to your account.

## Let's start with a question

**What is one web development problem you are working through right now?**

Share the context, the constraints, and what you have tried. Then take a look at someone else's question. A second perspective often reveals the simplest next step.

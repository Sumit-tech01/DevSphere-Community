# Security Policy

## Scope

DevSphere is a community repository, not a hosted software product. It does not contain a production application, database, authentication system, or user data store.

The security policy covers:

- The content and structure of this repository.
- GitHub Actions workflows and repository automation.
- Issue, pull request, and discussion templates.
- Links and resources published by the community.
- Brand assets and documentation that could be used for impersonation or phishing.

## Reporting a vulnerability

Please **do not open a public issue, discussion, or pull request** for a security concern.

**Preferred method:** use GitHub's private vulnerability reporting feature.

1. Open the repository's **Security** tab.
2. Select **Report a vulnerability**.
3. Describe the issue, affected files or links, and the potential impact.

If private vulnerability reporting is unavailable, contact the founder through the contact method listed on [@Sumit-tech01's GitHub profile](https://github.com/Sumit-tech01). Use a private channel and include the same information.

**Please include:**

- A clear description of the issue and its impact.
- The affected file, workflow, link, or repository feature.
- Steps to reproduce or a proof of concept, if safe to share.
- Any suggested mitigation.
- Whether the issue has been disclosed elsewhere.

**Please do not include:**

- Real credentials, access tokens, or personal data.
- Screenshots containing another person's private information.
- Exploit code that could cause harm if shared publicly.

## What to expect

DevSphere is maintained by volunteers. The following targets are best-effort, not a contractual guarantee:

| Stage | Target |
| --- | --- |
| Acknowledgment of report | Within 3 business days |
| Initial assessment and severity | Within 7 business days |
| Plan or fix for confirmed issues | Within 30 days, depending on complexity |
| Public disclosure | Coordinated after a fix or mitigation is available |

We will keep you informed when there is meaningful progress. If a report is out of scope, we will explain why.

## Safe harbor

We consider security research conducted in good faith to be authorized under this policy when it:

- Respects privacy and does not access, modify, or exfiltrate another person's data.
- Avoids disrupting GitHub, third-party services, or community members.
- Tests only repository content and automation that we control.
- Reports findings privately and gives us reasonable time to respond.
- Does not use social engineering, phishing, denial-of-service, or physical attacks.

We will not pursue legal action for accidental, good-faith violations of this policy. This safe harbor does not authorize activity outside our control or in violation of GitHub's terms.

## Out of scope

The following are generally out of scope unless they create a concrete security impact:

- Typos, formatting issues, or broken links.
- Theoretical vulnerabilities without a reproducible impact.
- Vulnerabilities in GitHub itself or in third-party services; report those to the relevant provider.
- Spam, harassment, or code-of-conduct concerns; use the [Code of Conduct](CODE_OF_CONDUCT.md) reporting process.
- Reports generated solely by automated scanners without analysis.
- Requests for payment, bounties, or sponsored disclosure. DevSphere does not operate a bug bounty program.

## Coordinated disclosure

Please give us a reasonable opportunity to investigate and address a confirmed issue before publishing details. We will coordinate a disclosure timeline with you and credit you if you wish. We may publicly document a fixed issue without identifying the reporter.

## Questions

For non-sensitive questions about this policy, open a **Questions & Help** discussion. For sensitive matters, use the private reporting method above.
